## Регламенты безопасности

### Защита представления для TLS, mTLS
- Протокол TLS 1.3
    - Параметры асимметричного шифрования для защиты handshake
        - Key Exchange Algorithms: TLS_DHE_RSA
          - 
        - Cipher suite: TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384
          - ECDHE - Elliptic Curve Diffie‑Hellman Ephemeral
            - сеансовые ключи не зависят от долгосрочного ключа сервера
            - ключи генерируются заново для каждого соединения
            - рукопожатие на основе алгоритма Диффи-Хеллмана, минимизация риска атаки на приватный ключ сервера
          - AES_256_GCM — алгоритм симметричного шифрования для защиты сообщений
            - Advanced Encryption Standard, 256-bit, повышенная безопасность
            - GCM режим работы AES, оптимизирован для современных CPU
          - SHA384 — хеш‑функция для
            - генерации сеансовых ключей, проверки целостности данных
            - 384-bit
      - Политика доверия
        - Trust Policy: Strict
            - verify_peer: true
            - verify_fail_if_no_peer_cert: true
            - verify_depth: 4
        - Certificate Verification Policies
            - check_expiration: true
            - check_revocation: true
            - check_hostname: true
            - check_signature: true
            - check_issuer: true

### Аутентификация для внешних систем
- Метод аутентификации: Закрытый API-ключ + Подписанный запрос
    - У клиента и сервера есть общий секрет (API-ключ), известный только им
    - Каждый запрос подписывается с помощью этого ключа
    - Сервер проверяет подпись → если валидна → пропускает
    - API-ключ хранится в Vault
        - защищен от mem dump атаки

### Хранение и доступ к секретам
- К секретам относятся: пароли, логины, сертификаты, приватные ключи, прочие чувствительные данные
- Хранятся только в Vault
- Запрещены к кэшированию
- Живут в памяти сервиса минимальное достаточное время

### partner-PACS-gateway → СКУД партнеров (HTTPS)
- Протокол представления: TLS
- Протокол прикладного уровня: HTTPS
- Аутентификация, Авторизация: Закрытый API-ключ + Подписанный запрос
- Логирование: внутренний лог сервиса

### СКУД партнеров → partner-PACS-events (socket)
- Протокол представления: TLS
- Протокол прикладного уровня: WSS (WebSocket Secure)
- Аутентификация: Закрытый API-ключ + Подписанный запрос
- Авторизация: по organization_id
- Шифрование на уровне представление данных
- Логирование: события остаются в partner-PACS-events, внутренний лог сервиса
- Внешний запрос к контейнеру через шлюз APISIX Gateway с плагинами:
    - Rate Limiting
    - HMAC Validation
    - IP Whitelist
    - WAF

## Внутренние взаимодействия между сервисами

### partner-PACS-actualizator, partner-PACS-controller → partner-PACS-db (JDBC)
- Протокол представления: mTLS
- Протокол прикладного уровня: JDBC, PostgreSQL over TLS
- Аутентификация: mTLS
- Авторизация: Role-based, `writer`
- Шифрование: `ssl=true&sslmode=require`
- Логирование: внутренний лог сервиса

### partner-PACS-actualizator ← partner-PACS-events (socket)
- Протокол представления: mTLS
- Протокол прикладного уровня: Kafka binary protocol over TCP
- Аутентификация: mTLS
- Авторизация: ACL (Access Control List)
- Шифрование: TLS
- Логирование: внутренний лог сервиса

### partner-PACS-controller → partner-PACS-gateaway (RPC)
- Протокол представления: mTLS
- Протокол прикладного уровня: gRPC + Protubuf
- Аутентификация: mTLS
- Авторизация: Role-based
- Шифрование: TLS
- Логирование: внутренний лог сервиса
